# [DOM XSS in `document.write` sink using source `location.search` inside a select element](https://portswigger.net/web-security/cross-site-scripting/dom-based/lab-document-write-sink-inside-select-element)

## **`الهدف`**
قم بتنفيذ هجوم `XSS` يتجاوز `select element` ويستدعي دالة `alert`.
## **`خطوات الحل`**
نقوم بالدخول على صفحة أى منتج فى الموقع ثم نقوم بحقن الأمر التالي فى الـ `URL` الخاص باللاب ونضغط `Enter` لننتهي من حل اللاب.
```html
&storeId="></select><img%20src=1%20onerror=alert(1)>
```
## **`ترقيع الثغرة`**
يجب التوقف عن تمرير المدخلات القادمة من المستخدم مثل المُعامل `storeId` عبر رابط الصفحة `location.search` مباشرة إلى مصبات غير آمنة `Sinks` مثل `document.write` والتي تقوم بدمج البيانات كأكواد `Raw HTML` وتسمح للمهاجم بكسر سياق القائمة المنسدلة، واستبدالها بواجهات `DOM` الآمنة مثل `document.createElement` لإنشاء خيارات القائمة `<option>` برمجياً.

ويجب تعقيم أو ترميز أي بيانات ديناميكية يتم استخراجها من الرابط قبل تمريرها أو دمجها في الصفحة، وذلك لضمان تحويل أي رموز خاصة `Special Characters` مثل أقواس الإغلاق `>` و `<` أو علامات التنصيص إلى كيانات برمجية `HTML Entities` لا يمكن للمتصفح تفسيرها كـ `Payload` خبيث يهدف لإنهاء وسم `</select>`.

وبما أن الهدف هنا هو مجرد عرض قيمة الـ `storeId` كخيار داخل القائمة المنسدلة في واجهة المستخدم `Frontend`، فيجب على المبرمجين الاعتماد على خصائص آمنة مثل `textContent` والتي تتعامل مع المدخلات كنص عادي `Plain Text` فقط، وتمنع تفعيل أي وسم `Tag` خبيث يتم حقنه مثل `<script>` أو `<img>`.

وكطبقة حماية إضافية `Defense in Depth`، يجب على السيرفر إرسال ترويسة سياسة أمان المحتوى `CSP` صارمة تمنع تنفيذ أكواد `JS` المدمجة `Inline Scripts` أو المنفذة عبر أحداث غير آمنة مثل `onerror`، فحتى لو فشل المطور في تأمين الكود برمجياً ونجح المهاجم في الخروج من الـ `select` وحقن الكود، سيتدخل المتصفح ويمنع تنفيذ الـ `alert`.
