# [DOM XSS in jQuery anchor `href` attribute sink using `location.search` source](https://portswigger.net/web-security/cross-site-scripting/dom-based/lab-jquery-href-attribute-sink)

## **`الهدف`**
قم بإنشاء رابط  يقوم بتفعيل تنبيه `document.cookie`.
## **`خطوات الحل`**
نقوم بالضغط على `Submit feedback` وبعد ذلك نقوم بحذف أي شئ بعد `?returnPath=` ثم نقوم بحقن الأمر التالي ليبدو هكذا ونضغط `Enter` لننتهي من حل اللاب.
```JS
?returnPath=javascript:alert(document.domain)
```
## **`ترقيع الثغرة`**
يجب التوقف عن تمرير المدخلات القادمة من المستخدم مثل المُعامل `returnPath` عبر رابط الصفحة `location.search` مباشرة إلى مصبات غير آمنة `Sinks` مثل خاصية `href` باستخدام مكتبة `jQuery` والتي تقوم بتعيين الرابط وتسمح للمهاجم بتمرير بروتوكولات قابلة للتنفيذ، واستبدال ذلك بالتحقق الصارم من مسار الرابط `URL Validation` قبل إسناده للوسم `<a>`.

ويجب تعقيم أو فحص أي بيانات ديناميكية يتم استخراجها من الرابط قبل تمريرها أو دمجها في الصفحة، وذلك لضمان أن الرابط يبدأ بمسار آمن `Safe Path` مثل `/` أو بروتوكول موثوق مثل `https://`، لمنع المتصفح من تفسيره كـ `Payload` خبيث يعتمد على بروتوكولات مثل `javascript:` ويهدف لتنفيذ أكواد خبيثة عند الضغط.

وبما أن الهدف هنا هو مجرد توفير مسار لعودة المستخدم للصفحة السابقة عبر رابط في واجهة المستخدم `Frontend`، فيجب على المبرمجين الاعتماد على التحقق عبر القوائم البيضاء `Allowlists` التي تسمح فقط بمسارات معروفة أو فحص هيكل الرابط، وتمنع تفعيل أي بروتوكول `URI Scheme` خبيث يتم حقنه مثل `javascript:alert`.

وكطبقة حماية إضافية `Defense in Depth`، يجب على السيرفر إرسال ترويسة سياسة أمان المحتوى `CSP` صارمة تمنع تنفيذ أكواد `JS` عبر الروابط المدمجة `javascript: URIs`، فحتى لو فشل المطور في تأمين الكود برمجياً ونجح المهاجم في الخروج عن المسار الطبيعي وحقن الكود داخل الـ `href`، سيتدخل المتصفح ويمنع تنفيذ الـ `alert`.
