# [DOM XSS in `document.write` sink using source `location.search`](https://portswigger.net/web-security/cross-site-scripting/dom-based/lab-document-write-sink)

## **`الهدف`**
قم بتنفيذ هجوم `XSS` يستدعي دالة `alert`.
## **`خطوات الحل`**
نقوم بحقن الأمر التالي فى خانة البحث ونضغط `Search` لننتهي من حل اللاب.
```html
"><svg onload=alert(1)>
```
## **`ترقيع الثغرة`**
يجب التوقف عن تمرير المدخلات القادمة من المستخدم عبر رابط الصفحة `location.search` مباشرة إلى مصبات غير آمنة `Sinks` مثل `document.write` والتي تقوم بدمج البيانات كأكواد `Raw HTML`، واستبدالها بواجهات `DOM` الآمنة مثل `document.createElement` لإنشاء العناصر.

ويجب ترميز أي بيانات ديناميكية يتم استخراجها من الرابط قبل تمريرها إلى خصائص مثل `src`، وذلك باستخدام دوال الترميز المخصصة للروابط مثل `encodeURIComponent` لضمان تحويل أي رموز خاصة `Special Characters` إلى نصوص مشفرة لا يمكن للمتصفح تفسيرها كـ `Payload` خبيث.

وإذا كان الهدف هو مجرد عرض كلمة البحث في واجهة المستخدم `Frontend`، فيجب على المبرمجين الاعتماد على خصائص آمنة مثل `textContent` والتي تتعامل مع المدخلات كنص عادي `Plain Text` فقط، وتمنع تفعيل أي وسم `Tag` خبيث مثل `svg`.

وكطبقة حماية إضافية، يجب على السيرفر إرسال ترويسة سياسة أمان المحتوى `CSP` صارمة تمنع تنفيذ أكواد `JS` المدمجة `Inline Scripts` أو المنفذة عبر أحداث مثل `onload`، فحتى لو فشل المطور في تأمين الكود برمجياً ونجح المهاجم في حقن الكود، سيتدخل المتصفح ويمنع تنفيذ الـ `alert()`.
